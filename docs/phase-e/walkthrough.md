# Phase E Consolidated Walkthrough: Fault & Chaos Resilience Testing

This document provides a comprehensive consolidated walkthrough of Phase E (Fault & Chaos Resilience Testing) implementation for the IGNIS project. It details the progression from initial clock and publisher abstractions to fully automated YAML-driven scenario execution with inline Docker network and container fault injections.

---

## 1. Phase E1: Foundations

### Common Event Model (`src/events.py`)
Standardized, transport-independent event classes defined using Python dataclasses with built-in serializability helper methods (`to_dict()` and `from_dict()`):
- `DecisionEvent`: Logs local fog state transitions, WHI ratings, confirmation counts, and clamping status.
- `AlertEvent`: Captures fire and system warnings generated by nodes.
- `ActionEvent`: Tracks local mitigation actions.
- `CloudReportEvent`: Captures telemetry updates and current buffer volumes forwarded to the cloud.
- `ScenarioEvent`: Monitors scenario status.

### Clock Abstraction (`src/clock.py`)
Injectable time wrapper that decouples runtime operations from python's system clock:
- `Clock`: Production time tracking. Delegates to `time.time()`, `time.sleep()`, and `time.strftime()`.
- `MockClock`: Manual simulated clock tracking (`advance(seconds)`). Allows unit tests to verify time-sensitive events (such as TTL expirations) instantly and deterministically.

### Reusable Buffered Publisher (`src/buffered_publisher.py`)
Thread-safe wrapper for Paho MQTT client instances:
- Implements a FIFO queue backed by `collections.deque(maxlen=5000)`.
- If connected, dispatches messages directly. If disconnected, caches them internally.
- `flush()`: Automatically drains enqueued items sequentially once broker connectivity is restored.

## 2. Phase E2: Fog Node Cloud-Disconnect Resilience

### Abstraction Integration (`src/fog_node_runner.py`)
- Integrated `Clock` and `BufferedPublisher` into the standard runner lifecycle.
- Wrapped client disconnect and connect callbacks:
  - `on_disconnect_cloud`: Marks the publisher as disconnected.
  - `on_connect_cloud`: Marks the publisher as connected and calls `flush()` to drain the queue.
- Property fallbacks were created for `clock` and `cloud_publisher` to maintain backwards compatibility for legacy mock tests.

### Local Continuity Logging
- If local ORANGE/RED risk mitigations execute during a cloud connection outage, the runner generates stdout logs prefixed with `[Offline Continuity] Action Log: ...` to ensure on-site operators retain visibility into emergency actions.

## 3. Phase E3: YAML Scenario Library & Scenario Package

### Standardized YAML Scenarios (`scenarios/`)
Converted test case declarations from code-generated scripts into YAML definitions:
- `s1_normal.yaml`: Normal ambient baseline drifts.
- `s2_slow_risk.yaml`: Elevating hazard parameters crossing YELLOW risk.
- `s3_sudden_ignition.yaml`: Multi-sensor fire spikes.
- `s4_sensor_fault.yaml`: Single sensor fault validating clamping rules.
- `s5_cloud_outage.yaml`: Sudden ignition with cloud partition chaos (E5).
- `s6_lateral_spread.yaml`: Wind-driven fire propagation.
- `s7_multi_zone.yaml`: Concurrent parallel zone fires (E5).

### Modular Scenarios Package (`src/scenarios/`)
- `results.py`: Decouples outcome models (`ScenarioMetric`, `ScenarioResult`).
- `base_scenario.py`: Defines the `BaseScenario` interface and `GenericScenario` step-by-step orchestrator loop.
- `scenario_runner.py`: Coordinates YAML loading, MQTT event subscription, statistical trials, and validation.
- `scenario_registry.py`: Holds mappings from scenario IDs to classes.
- `scenario_s1_s2_s3.py`, `scenario_s4.py`, `scenario_s6.py`: Custom subclasses for concrete executions.

## 4. Phase E4: Chaos Controller Service

### Docker Adapter (`src/chaos_controller/docker_adapter.py`)
Host-side wrapper for the Docker Python SDK:
- Employs lazy client instantiation (`@property client`) to avoid Docker socket errors when importing modules inside isolated unit tests.
- Abstractly exposes network `disconnect`/`connect` and container `stop`/`restart` APIs.

### FastAPI REST Service (`src/chaos_controller/routes.py` & `app.py`)
Launches a host-side FastAPI service on port 9001:
- `POST /api/chaos/disconnect_cloud`: Disconnects zone fog node container from `cloud-net` for realistic partition testing.
- `POST /api/chaos/restore_cloud`: Restores network interface.
- `POST /api/chaos/kill_container` / `/restart_container`: Halts or restarts containers.
- Uses FastAPI `BackgroundTasks` to schedule auto-recovery actions.

### Network Isolation (`docker-compose.yml`)
- Introduced the `cloud-net` bridge network.
- Linked fog node containers to both `default` and `cloud-net`. Disconnecting a container from `cloud-net` blocks cloud data exchange while local operations remain functional.

## 5. Phase E5: Scenario Automation with Fault Injection

### Inline Chaos Actions (`src/scenarios/base_scenario.py`)
`GenericScenario` automatically checks for `chaos_actions` in the YAML scenario:
- Evaluates elapsed simulated execution time.
- If a target offset matches, triggers POST requests to the local Chaos Controller REST endpoint.
- Compatible with `MockClock` in tests since triggering is tied directly to step progression.

### Outage and Concurrency Scenarios (`scenario_s5.py` & `scenario_s7.py`)
- `ScenarioS5` (Cloud Outage during Event): Outage is scheduled at step 2 (t=8s) and recovers at t=28s, checking the buffering and flush progression.
- `ScenarioS7` (Concurrent Multi-Zone Escalation): Orchestrates parallel fire escalations in both `4A` and `4B` zones using python threading, and aggregates outcomes.

## 6. Phase E6: Metrics Collector & Report Generator

### Metrics Calculation CLI (`src/metrics_collector.py`)
Computes five core Section 7 metrics:
- **Decision Latency**: Aggregates response delay (`decision_timestamp` - `sensor_timestamp`) from Scenario S3.
- **Lateral Propagation Time**: Computes time delta between Zone 4B warnings and neighbor Zone 4C preemptive transitions.
- **False-Positive Rate**: Clamping accuracy verification under single sensor failures.
- **Offline Continuity**: Telemetry buffering volumes and recovery flush success rates.
- **Concurrent-Zone Integrity**: Packet loss and cross-talk rates under parallel streams.

### Plotted Visualizations and Reporting (`src/report_generator.py`)
- Employs Matplotlib to output five visual trend charts into `docs/phase-e/charts/`.
- Compiles the final dissertation-ready summary document at `docs/phase-e/section7_metrics_report.md`.
